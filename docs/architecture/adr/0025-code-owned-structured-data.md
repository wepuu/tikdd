# ADR-0025: Code-owned structured data from eligible published content

Status: Accepted — 2026-09-08

## Context

TikDD already derives canonical paths, hreflang, sitemap membership, and an SEO passport from
one validated published content snapshot. The passport names a page-level structured-data template,
but the public Web does not currently emit JSON-LD.

The public site needs a small, deterministic structured-data foundation without creating a second
content authority. Raw JSON-LD from Admin would allow scripts, remote entities, arbitrary URLs, or
claims that do not match visible content. Dynamic task, result, Delivery, API, and Admin routes
must never become search content.

## Decision

- Structured data is generated by code from the validated published snapshot and the same visible
  page copy rendered by Web. It is never stored as raw JSON-LD and is never accepted as an Admin
  field.
- The shared SEO passport reports a bounded set of applicable templates:
  `SoftwareApplication`, `FAQPage`, `HowTo`, and `BreadcrumbList`.
- A document is emitted only when the page is `indexableEligible` and the required visible fields
  for that template are present. Experimental, noindex, fallback-only, draft, private, and dynamic
  pages emit no public structured data.
- JSON-LD is emitted as one server-rendered `application/ld+json` document. The serializer escapes
  script-sensitive characters and does not include submitted URLs, task IDs, Provider details,
  delivery URLs, credentials, or remote entities.
- `SoftwareApplication` is limited to the indexable homepage. `FAQPage` and `HowTo` require the
  corresponding visible FAQ and step content. `BreadcrumbList` is emitted only for an eligible
  non-root content page with a canonical path.
- The existing content publication, eligibility, canonical, robots, sitemap, and noindex rules
  remain authoritative. This decision does not promote X or Instagram, start Admin, or change
  Provider rollout.

## Consequences

The homepage can gain a small, reviewable JSON-LD graph without a database migration or a new
editorial store. The same builder can later support stable platform pages after their existing SEO
eligibility gate passes. Noindex Instagram Beta pages remain safe for human review and do not gain
indexing signals prematurely.

The structured-data contract and renderer must be tested against visible localized content,
canonical paths, eligibility suppression, and script-injection attempts. Any future schema type or
new source field requires a code review and a follow-up ADR if it changes the publication boundary.
