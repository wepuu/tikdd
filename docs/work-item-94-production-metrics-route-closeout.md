# Work Item 94 — Production metrics and route-health closeout

## Baseline

This work starts from deployed `main@1a3b28518cde9d87b1ca3d47af63ab2874777f83` after the WI93
SaveFromIns deadline release. Instagram is enabled through the unique `savefromins / instagram /
nl` rule at revision 23 and full allocation. The owner has completed several successful Instagram
downloads. Admin is available, calibration remains off, and the other five production platform
states are unchanged.

## Problem

The retention cleanup changes a task's live status to `expired` while retaining its normalized
`result` or `error` payload. The Admin Beta aggregate currently groups only by the live status, so
a previously successful task can later be counted as expired and lower the displayed success rate.
The route view also exposes only a coarse half-open state, making it difficult to tell whether a
Provider is waiting for recovery or has no usable evidence.

## Implementation

- Normalize read-only task aggregates from the retained payload: `result` means succeeded, `error`
  means failed, and `expired` without either payload remains a genuine uncompleted expiration.
- Keep task, Provider-attempt, Delivery-ticket, redirect-validation, and browser-handoff metrics
  as separate measures. A browser handoff never becomes a claim that a file was saved.
- Expose the sanitized circuit `recoverySuccessCount` in the existing Admin route summary. Older
  Admin snapshots remain valid because the field is optional.
- Display the recovery count only for a half-open route; do not add a manual circuit reset command.
- Update WI93, the SaveFromIns record, and the roadmap with the actual production closeout.
- Do not add a migration, public endpoint, Provider adapter, route, retry, Delivery mode, rollout
  authority, synthetic Provider probe, or calibration profile.

## Tests

- Verify expired tasks with a retained result are counted as succeeded.
- Verify expired tasks with a retained error are counted as failed.
- Verify expired tasks with neither payload remain expired and active tasks stay outside the
  terminal success-rate denominator.
- Verify Admin route contracts accept legacy snapshots without the optional recovery field and
  expose the sanitized recovery count for current snapshots.
- Verify no task IDs, URLs, Provider payloads, CDN addresses, Cookies, or tokens enter the Admin
  response.
- Run targeted persistence/Admin tests, `pnpm check`, `git diff --check`, and production Compose
  validation.
